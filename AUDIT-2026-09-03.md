## 3. Findings P0 (stop-saignement)

### P0-1 · Bypass signature webhook Stripe
`job_xpress/api/stripe_webhook.py:299-303`
```python
webhook_secret = getattr(settings, "STRIPE_WEBHOOK_SECRET", None)
if stripe_signature and webhook_secret:
    if not verify_stripe_signature(payload, stripe_signature, webhook_secret):
        raise HTTPException(401, ...)
```
+ `:57-59` fail-open si secret vide.
**Impact** : POST `/webhooks/stripe` **sans header `Stripe-Signature`** saute toute vérif → faux `checkout.session.completed` avec `customer_email` = email de l'attaquant → `upgrade_user_subscription` via admin_client (bypass RLS) = abonnement PRO + crédits gratuits. `invoice.payment_succeeded` = reset crédits à volonté. Le secret EST bien posé dans Render (vérifié via API), la faille est dans le `if ... and ...`, pas dans la config.
**Fix** :
```python
if not stripe_signature or not webhook_secret:
    raise HTTPException(401, "Missing signature")
event = stripe.Webhook.construct_event(payload, stripe_signature, webhook_secret)
```
+ test "header absent → 401" (le test actuel `test_stripe_webhook.py:64-68` valide le fail-open — le corriger).

### P0-2 · XSS sur le chat JobyJoba (frontend)
`frontend/src/app/dashboard/chat/[applicationId]/page.tsx:298-304`
```tsx
dangerouslySetInnerHTML={{ __html: msg.content
  .replace(/\*\*(.*?)\*\*/g, '<strong>$1</strong>') }}
```
**Impact** : contenu de session chat pilotable via les endpoints chat → exécution de script, vol de cookies session Supabase. Le composant `SanitizedHTML` existe déjà (utilisé dans inbox).
**Fix** : `<SanitizedHTML html={...} />` ou `DOMPurify.sanitize()` avant `__html`.

### P0-3 · Next.js 16.0.10 vulnérable, auth portée par le proxy
`frontend/package.json:26` — CVE-2026-44575 / CVE-2026-45109 (bypass autorisation via URLs `.rsc`/prefetch, précisément quand l'auth est dans middleware/proxy — le cas ici, aucun re-check `getUser()` dans les pages du dashboard).
**Fix** : `npm i next@^16.2.11` + re-vérifier `getUser()` server-side dans chaque page protégée.

### P0-4 · Prod Render dégradée : config env incomplète
Vérifié via API Render (20 env keys) + probe live :
- **`SUPABASE_URL` et `SUPABASE_KEY` absents** des env vars → `/health` live renvoie `"supabase":"unhealthy"` ; defaults chaîne vide dans `core/config.py:17-18`.
- `STRIPE_SECRET_KEY` absent aussi (seul le webhook secret est là) — checkout server-side à vérifier.
- **Drift blueprint** : `render.yaml` déclare runtime docker + healthCheck `/health` + plan free avec env list ; le service réel est runtime **python**, `healthCheckPath: ""` → le blueprint n'a jamais été linké. Render ne se repose sur rien de versionné.
**Fix** : linker le blueprint Render sur le repo (ou supprimer render.yaml pour cesser de mentir), ajouter les env manquantes, activer healthCheckPath=/health.

## 4. Findings P1

### P1-1 · Webhook Tally non authentifié
`job_xpress/main.py:418-422` — seul garde-fou : rate limit 10/min. Aucun secret/signature Tally vérifié. N'importe qui déclenche le pipeline : appels LLM facturés, **emails Brevo envoyés à toute adresse** (vecteur spam), PII en base. Fix : header `X-Webhook-Key` comparé en `hmac.compare_digest`.

### P1-2 · CV uploadés en bucket public
`job_xpress/api/profile_endpoints.py:383-390` — `get_public_url` sur `cvs` : CV complets (nom, tél, adresse, historique pro) accessibles sans JWT si l'URL fuit. RGPD. Fix : bucket privé + `create_signed_url` TTL court.

### P1-3 · Vraies clés live dans le workspace local
`job_xpress/.env` — `SUPABASE_SERVICE_KEY` (service_role !) + `OPENAI_API_KEY` sk-proj + `BREVO_API_KEY` en clair. Non commités (historique clean, vérifié), mais repo public + un `git add -f` distrait = compromission totale DB. Fix : stocker hors workspace, **rotation des clés** recommandée.

### P1-4 · Upgrade billing par email auto-déclaré
`job_xpress/services/database.py:172-191` + `stripe_webhook.py:75-106` — attribution user par `customer_email` de l'événement. Fix : `metadata.user_id` injecté au checkout, binder sur `stripe_customer_id`.

### P1-5 · CI : prod déployée sur commit CI rouge + frontend hors CI
- Le commit déployé live (`7719101`) a un **run CI en failure** ; Render auto-déploie sans gate (`autoDeploy: yes`, pas de branch protection).
- `ci.yml:5-13` paths limités à `job_xpress/**` → le frontend n'est jamais buildé/linté/testé en CI ; ruff/bandit/safety en `continue-on-error`.
Fix : branch protection `main` requiring checks + job frontend.

### P1-6 · Middleware Supabase fail-open + gating admin client-side
- `src/lib/supabase/middleware.ts:26-29, 78-82` : `catch` → `NextResponse.next()` = dashboard servi sur erreur Supabase. Fix : redirect `/login` sur erreur en chemin protégé.
- `src/app/dashboard/page.tsx:115-125` : `NEXT_PUBLIC_ADMIN_USER_ID` avec **UUID admin fallback en dur** dans le bundle public. Fix : flag `is_admin` renvoyé par `/api/v2/me`.

## 5. Findings P2 (sélection)
- **Route notifications dupliquée shadowée** : version sans filtre `user_id` (`api/notifications_chat.py:95-105`) écrase la version filtrée (`api/dashboard_endpoints.py:117-121`) selon l'ordre d'inclusion `main.py:143-147` ; protection = RLS seule.
- **IDOR d'écriture sans assertion ownership** : `search_endpoints.py:343, 461, 490`, `notifications_chat.py:141` — `.eq("id", ...)` sans `.eq("user_id", ...)` (bloqués par RLS aujourd'hui ; coût zero d'ajouter le filtre).
- **Policy DELETE manquante** sur `applications_v2` → endpoint delete mort (404 pour tous).
- `/health`, `/health/tasks`, `/health/redis`, `/webhooks/stripe/health` publics : révèlent version, env, intégrations configurées et **si le webhook secret Stripe est posé** (`stripe_webhook.py:509-513`).
- Messages d'erreur internes + `details` sérialisés dans les 500 (`core/error_handlers.py:62`).
- `cache_service.py:26` SQLite `cache.db` = volatil sur Render free (redémarrs/sleep fréquents) : la file `pending_tasks` contient des payloads webhook avec PII complète, perdue à chaque cold start. Fix : table Postgres ou le Redis déjà présent (`REDIS_URL` existe).
- Upload avatar : `content_type` client-contrôlé, fichier lu entier **avant** le check de taille (`profile_endpoints.py:250-263`) → spoofing MIME + OOM. Fix magic-bytes + chunked read.
- SSRF indirect via `cv_url` free-form passé à Mistral (`ocr_service.py:66-69`). Fix allowlist hosts.
- `requirements.txt` : ranges `>=` uniquement, 0 lockfile → build non reproductible ; Python 3.10 CI / 3.11 Docker / 3.13 local = drift.
- Bugs : `dashboard_endpoints.py:91-95` champ inexistant `has_first_search` → 500 dans le chemin d'erreur ; `api.ts:264` redirect 401 vers `/auth/login` (route inexistante, c'est `/login`) ; `api.ts:217-219` token factice si `NEXT_PUBLIC_MODE=DEVELOPMENT` ; vestiges `job_xpress/0.20.0` et `test_local.py` avec email perso en dur.
- Frontend sans CSP/headers de sécurité (`next.config.ts:4-13`, netlify.toml) ; monolithes `apply/page.tsx` 1041 LoC / `settings/page.tsx` 974 LoC ; 12 fetch hors `api.ts`.

## 6. Points forts (honnêteté oblige)
- `core/auth.py` : validation JWT propre, fail-closed si secret absent, aud/sub/exp vérifiés.
- Migrations RLS 018/019 sérieuses : policies own-only, `(SELECT auth.uid())`, SECURITY DEFINER verrouillés.

- Zéro secret dans l'historique git. Observabilité Sentry/Axiom/request_id câblée.
- Idempotence Stripe events (mig 011), circuit breaker + retry sur les appels externes.
