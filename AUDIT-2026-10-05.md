## 9. Correctif post-audit — panne du chat LLM en prod (soirée du 05/10)

**Découverte après coup : toutes les fonctions IA passant par le provider LLM unique étaient en
panne en prod depuis au moins le 02/10** — chat JobyJoba, scoring, lettres, analyse d'offres.

- **Impact constaté** : la seule conversion `sign_up` du 02/10 est un utilisateur réel (compte
  Google confirmé dans les bases prod). Dès sa première demande, JobyJoba lui a répondu « erreur
  technique » ; il n'est jamais revenu (0 recherche, 0 candidature, 0 reconnexion).
- **Diagnostic** : `POST https://opencode.ai/zen/go/v1/chat/completions → HTTP 401 Invalid API key`
  (test direct depuis le VPS). Trois causes cumulées : clé OpenCode obsolète, base URL encore sur
  l'ancienne route, et en-tête `x-opencode-session` absent — ce dernier est exigé par le routage
  OpenCode Go.
- **Correctif déployé le 05/10** :
  - nouvelle clé (`oc_sk_…` issue de `analytics-credentials/.env`) branchée en prod
  - base URL `https://opencode.ai/zen/go/v1`
  - modèles réels : `mimo-v2.5` (main), `mimo-v2.5-pro` (premium), `mimo-v2.6-flash` (fast)
  - en-tête `x-opencode-session` ajouté au provider (commit `9334d33`)
  - image API reconstruite, conteneur unique relancé (healthy)
- **Vérification** : endpoint chat appelé avec une session authentifiée → réponse réelle de
  l'assistant ; logs API sans erreur ; variables d'env du conteneur conformes.
- **Reste ouvert** : l'ancienne clé est encore écrite en clair dans `job_xpress/.env` et
  `.env.local` — **à révoquer chez le fournisseur**, pas seulement remplacer (voir §7, avant tout).
